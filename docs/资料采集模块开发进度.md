# 资料采集模块开发进度

## 2026-05-29 重新梳理

### 模块定位

资料采集模块拆分为两个子模块：

| 子模块 | 核心目标 | 主要产物 |
| --- | --- | --- |
| 知识点采集 | 从教材、考试分析、复习讲义中归纳知识点、考点、历史数据、命题分析 | 知识点 JSON、`knowledge_points`、`topics`、知识点来源记录 |
| 题库采集 | 从 PDF/Word/图片中识别题目、答案、解析、公式和图形 | 题目 JSON、`question_banks`、`questions`、`question_assets` |

两部分最终要打通：

1. 题目关联知识点，写入 `question_knowledge_points`。
2. 历史真题按知识点、年份、题型、分值统计。
3. 统计结果供【统计分析】模块使用，例如知识点热度、分值分布、薄弱点分析。

### JSON 与数据库关系

建议采用“JSON 中间层 + SQLite 权威库”的流程，而不是只选其一。

原因：

- AI 归纳和题目识别天然适合先输出 JSON，便于人工校对、重跑、对比不同模型结果。
- SQLite 更适合作为应用运行时的权威数据源，支持查询、统计、关联、去重和版本管理。
- 对于公式、图形、截图等非文本内容，JSON 只记录结构和引用，真实文件落盘后由数据库记录路径。

推荐流程：

```text
原始资料
  -> 文本/图片/页码抽取
  -> AI 生成结构化 JSON 草稿
  -> 人工校对 JSON
  -> 导入 SQLite
  -> 规则 + AI 辅助关联知识点
  -> 统计分析
```

落地原则：

- JSON 是“草稿、备份、可审计中间产物”。
- SQLite 是“应用读取、写回、统计分析的唯一权威数据源”。
- 数据库写入后仍保留 JSON 导出能力，便于回溯和迁移。

### 题库采集规划

- 前端校对界面显示截图，允许用户补录 LaTeX 或文字说明。

## 2026-05-30 知识点采集策略调整

### 核心原则

- 仅整理最新版本的知识点，以 `2026年语文` 为起点。
- 更早年份的知识点暂不作为知识点数据库的主要数据源，学生可以通过阅读原始资料或历年试卷自行学习。
- 目前保留的知识点数据仅限于已经人工生成并校对的专题：`专题01_名篇名句默写`、`专题02_语言积累与表达`。
- 其他自动生成且未人工确认的知识点数据应清空或不再继续累积，以免数据库被低质量数据污染。

### 实施方案

1. 先从 `2026年语文` 开始，验证知识点采集模块的可行性。
2. 逐步完善采集流程后，再考虑扩展到其他学科。
3. 记录优化过程与关键决策在本开发日志中，保证后续回溯可查。

### 具体执行建议

- 先清理掉已存在但不完整、未校对的知识点记录，只保留人工确认的专题数据。
- 以 `2026` 为默认版本，知识点统计和展示优先使用最新版本数据。
- 在知识点入库阶段加入“人工校对确认”门槛，避免自动生成内容直接写入 `knowledge_points`。
- 目前的目标不是“大量覆盖”，而是“从 2026 语文开始做深、做准”。

## 2026-06-01 功能构思：题库题目自动映射到知识点

### 目标

在知识库已经由 `data/docs` 下 2026 年语文、数学、外语 JSON 建立后，让题库中的每道题自动生成候选知识点，并写入 `question_knowledge_points`。自动映射不应直接视为最终结论，而应作为“高置信度自动通过、低置信度人工确认”的候选流程。

### 总体思路

采用分层映射策略：

1. 规则映射：低成本、可解释，先用题型、题干关键词、答案解析关键词、来源专题、年份、题号段做初筛。
2. 向量/相似度映射：把题干、解析、知识点标题、知识点说明转成可比较文本，计算相似度，补足规则无法覆盖的题目。
3. AI 复核映射：只对低置信度或多候选冲突题目调用 AI，让 AI 从候选知识点中选择，不让 AI 在全库自由发挥。
4. 人工确认：前端展示候选知识点、置信度、命中理由，允许确认、删除、替换、添加。
5. 结果入库：确认后写入 `question_knowledge_points`，并记录 `source`、`confidence`、`note`。

### 数据来源

题目侧可使用：

- `questions.content`：题干。
- `questions.source_answer`：参考答案。
- `questions.analysis`：解析。
- `questions.type`：题型。
- `questions.score`：分值。
- `questions.year` 通过 `question_banks.year` 获取。
- `questions.raw_json`：保留 qwen 源结构，数学解答题小题信息也在其中。
- `question_assets`：后续可加入图片、公式、PDF 页码辅助判断。

知识点侧可使用：

- `knowledge_points.name`：扁平知识点名称。
- `knowledge_points.category`：知识点分类。
- `knowledge_points.description`：知识点描述。
- `topic_knowledge_points`：专题与知识点关系。
- `knowledge_nodes.title`、`knowledge_nodes.content_json`：树状知识图谱节点内容。
- `knowledge_edges`：前置/后续/包含关系，后续可用于扩展相邻候选。

### 最小可行版本

先实现一个可控的规则候选脚本，例如：

```bash
python backend/scripts/link_question_knowledge.py --subject math --reset
```

逻辑：

1. 读取指定学科的 `questions`。
2. 拼接题干、答案、解析为 `question_text`。
3. 读取同学科 `knowledge_points` 与 `topic_knowledge_points`。
4. 建立关键词词典：
   - 知识点名称本身；
   - 知识点描述中的高频关键词；
   - 数学公式关键词，如函数、导数、数列、圆锥曲线、概率、立体几何；
   - 语文题型关键词，如文言文、现代文、作文、论证、意象；
   - 英语题型关键词，如 reading、cloze、grammar、translation、writing。
5. 对每道题计算候选得分：
   - 标题/知识点名称直接命中：高分；
   - 解析中命中：中高分；
   - 题干中命中：中分；
   - 题型与专题匹配：加分；
   - 同一题库来源专题匹配：加分。
6. 取前 3-5 个候选写入 `question_knowledge_points`：
   - `confidence >= 0.85`：可标记为高置信度；
   - `0.6 <= confidence < 0.85`：需要人工确认；
   - `< 0.6`：默认不写入或只作为临时候选。

### 建议新增候选表

当前 `question_knowledge_points` 更适合保存已确认或准确认的映射。为了支持人工审核，建议新增候选表：

```sql
CREATE TABLE question_knowledge_candidates (
    id TEXT PRIMARY KEY,
    question_id TEXT NOT NULL,
    knowledge_point_id TEXT NOT NULL,
    confidence REAL NOT NULL DEFAULT 0.5,
    source TEXT NOT NULL DEFAULT 'rule',
    reason TEXT DEFAULT '',
    status TEXT NOT NULL DEFAULT 'pending',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

字段说明：

- `source`：`rule`、`embedding`、`ai`、`manual`。
- `reason`：记录命中原因，例如“题干命中：数列；解析命中：等比数列”。
- `status`：`pending`、`accepted`、`rejected`。

人工确认后，再把 `accepted` 的候选写入 `question_knowledge_points`。

### AI 辅助策略

AI 不直接全库匹配，而是做候选重排：

1. 规则/相似度先筛出 10 个以内候选知识点。
2. 把题干、解析、候选知识点列表发给 AI。
3. 要求 AI 只从候选中选择 1-3 个，并给出理由。
4. AI 结果写入候选表，`source='ai'`，置信度不超过规则最高候选，避免 AI 过度覆盖确定规则。

这样可以降低 token 消耗，也能减少 AI 幻觉。

### 前端交互构思

在题库采集或题库详情中增加“知识点映射”区域：

- 每道题展示候选知识点标签。
- 标签显示置信度和来源，例如 `规则 0.92`、`AI 0.78`。
- 点击候选可查看命中理由。
- 支持“确认全部高置信度”。
- 支持单题修改：删除候选、搜索知识点、手动添加。
- 支持按状态筛选：未映射、待确认、已确认、低置信度。

确认后写入：

- `question_knowledge_points.source='manual'`：人工最终确认。
- `question_knowledge_points.confidence=1.0`：人工确认可视为最高置信度。

### 难度与知识点联动

后续映射知识点时可同步给出难度建议：

- 题目涉及单一基础知识点：偏易。
- 涉及多个知识点且需要组合推理：中等。
- 涉及跨专题综合、压轴题、多个小问递进：偏难。

难度建议先写入候选结果或 `questions.difficulty` 的草稿字段，人工确认后再保存。

### 实施顺序

1. 先完成数学 2023-2026 qwen 真题导入与 21 大题口径核对。
2. 编写 `link_question_knowledge.py` 的新版规则候选逻辑，先只针对数学做验证。
3. 新增 `question_knowledge_candidates` 表，用于保存待确认候选。
4. 增加后端接口：
   - `POST /api/knowledge/generate-question-candidates`
   - `GET /api/knowledge/question-candidates?bankId=...`
   - `POST /api/knowledge/confirm-question-candidates`
5. 在前端题库详情或资料采集页加入候选确认 UI。
6. 数学验证稳定后，再扩展到语文和英语。

### 风险与注意事项

- 不要一开始就让 AI 对全量知识点自由匹配，成本高且不稳定。
- 不要把低置信度候选直接写成最终映射，否则会污染后续学生能力图谱。
- 数学题中的公式、图形、条件缺失会影响匹配，后续应结合 `question_assets` 和 PDF 页码校对。
- 语文和英语的知识点粒度可能比数学更宽，需要允许一题对应多个能力点或题型点。
- 自动映射结果必须可追溯：至少记录来源、置信度、命中理由和确认状态。
