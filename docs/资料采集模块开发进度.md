# 资料采集模块开发进度

## 2026-05-29 重新梳理

### 模块定位

资料采集模块拆分为两个子模块：

| 子模块 | 核心目标 | 主要产物 |
| --- | --- | --- |
| 知识点采集 | 从教材、考试分析、复习讲义中归纳知识点、考点、历史数据、命题分析 | 知识点 JSON、`knowledge_points`、`topics`、知识点来源记录 |
| 题库采集 | 从 PDF/Word/图片中识别题目、答案、解析、公式和图形 | 题目 JSON、`question_banks`、`questions`、`question_assets` |

两部分最终要打通：

1. 题目关联知识点，写入 `question_knowledge_points`。
2. 历史真题按知识点、年份、题型、分值统计。
3. 统计结果供【统计分析】模块使用，例如知识点热度、分值分布、薄弱点分析。

### JSON 与数据库关系

建议采用“JSON 中间层 + SQLite 权威库”的流程，而不是只选其一。

原因：

- AI 归纳和题目识别天然适合先输出 JSON，便于人工校对、重跑、对比不同模型结果。
- SQLite 更适合作为应用运行时的权威数据源，支持查询、统计、关联、去重和版本管理。
- 对于公式、图形、截图等非文本内容，JSON 只记录结构和引用，真实文件落盘后由数据库记录路径。

推荐流程：

```text
原始资料
  -> 文本/图片/页码抽取
  -> AI 生成结构化 JSON 草稿
  -> 人工校对 JSON
  -> 导入 SQLite
  -> 规则 + AI 辅助关联知识点
  -> 统计分析
```

落地原则：

- JSON 是“草稿、备份、可审计中间产物”。
- SQLite 是“应用读取、写回、统计分析的唯一权威数据源”。
- 数据库写入后仍保留 JSON 导出能力，便于回溯和迁移。

- `AIAnswerReference` 先从 JSON 搜索答案库，再从数据库取 `source_answer`。后续应改为优先从 SQLite 读取，JSON 只做备份。

```json
  ]

```

### 题库采集规划

题库采集继续沿用现有解析页面，但需要升级为三步：

1. 抽取：PDF/Word 提取文本，公式和图形先保留页码/截图。
2. 校对：人工确认题干、答案、解析、题号、分值、题型。
3. 入库：写入 SQLite，并同步生成 JSON 备份。

公式与图片建议：

- PDF 文本能识别的公式先保存在 `questions.content/source_answer/analysis`。
- 识别不稳定的公式、图形、整题图片，截图为文件，建议目录为 `data/question_assets/{bank_id}/{question_id}/`。
- 数据库 `question_assets` 记录 `asset_type`、`file_path`、`page_number`、`bbox_json`、`description`。
- 前端校对界面显示截图，允许用户补录 LaTeX 或文字说明。

### 当前结论

数据库改动总体可行，方向也对：保留 `source_answer`，新增答案讨论字段和资产/知识点关联表，能支撑后续核心功能。

但当前仍处于“JSON 与数据库混用”的过渡态，最大风险不是表结构，而是读写入口不统一。下一步应先把题库读取、保存、删除、答案修正统一到 SQLite，再保留 JSON 作为导出备份。这样后续知识点归类、真题统计和图片资产管理才不会互相打架。

## 2026-05-29 知识点采集测试修复

### 已修复

- 修复知识点采集中文件选择后，浏览器文件框仍显示“未选择任何文件”的误导问题。
  - 原因：知识点面板作为内部 React 组件渲染，父组件状态更新时会重挂载，导致原生 file input 显示状态被清空。
  - 处理：改为普通渲染函数，并在文件框下方显示“已选择：文件名”。
- 强化知识点 JSON 生成提示词：
  - 新增 `examHistory` 字段，要求完整提取“年份/分值/考点/篇目”命题分析表。
  - 新增 `requiredTexts` 字段，要求完整提取“春考考查篇目”并按册别分组。
  - 明确要求保留高频篇目、易错字词、直接默写、情景默写、文学常识、文化常识等信息。
  - 明确禁止编造，缺失信息使用空数组或 `null`。
- `/api/ai/ask` 支持传入 `numPredict` 和 `temperature`，知识点采集调用时使用 `numPredict: 4096`、`temperature: 0.1`，减少 JSON 信息不完整的问题。

### 说明

后台出现的 PDF warning，如 `Unsupported: field.type of Link`、`TT: undefined function`，来自 PDF 文本抽取库处理字体、链接和表单字段时的提示。只要文本能成功抽取，它们不是 AI 生成 JSON 的直接错误。
